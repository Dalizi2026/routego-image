# Codex 对话参考图与多图编辑工作流

**版本目标：v1.0.2**

Routego Image 的参考图生成和多图图片编辑在 Codex 对话中完成，不需要进入 Studio 工作台。本文只说明 Codex 对话附件的使用规则；不改变 Studio 界面、Studio 创建合同、Studio 上传接口，也不增加 Gemini、Grok 或其他模型。

## 用户操作

在同一条 Codex 消息中按需要的顺序附上图片，并写清楚希望生成或编辑的结果。

### 单图编辑或参考图生图

附上一张图片并说明修改目标。例如：

> 把这张产品图改为雾面深灰色工业设计展板，保留产品轮廓、比例和主要结构，不要加入品牌标志。

第一张图片是主图。Codex 使用 `routego_edit` 执行一次编辑；如果没有额外参考图，主图同时提供待保留的核心主体。

### 多图图片编辑

第一张图片始终是主图，随后附上的图片是参考图。例如：

> 第一张是手表产品图，第二张是模特图。让第二张中的模特自然佩戴第一张的手表；保留手表的外形、表盘和材质，保留模特身份与背景，不要添加文字或水印。

Codex 会把第一张作为编辑目标，第二张及后续图片按附件顺序传给供应商。文字中明确说明的角色优先：产品使用 `product`、模特或人物使用 `character`、风格使用 `style`、构图使用 `composition` 或 `layout`、背景使用 `background`；未说明时使用普通 `reference`。

## 图片顺序与边界

- 只使用当前这条消息中明确附上的图片路径；不会扫描文件夹、猜测路径、使用历史消息中的附件或图库图片。
- 第 1 张为主图（编辑目标）。
- 第 2 至第 6 张为有序参考图，最多 5 张。
- 一次最多 6 张实际输入图。第 7 张图片会在本地被拒绝，绝不发起供应商请求。
- 若用户没有给出保留条件，Codex 默认要求保留主图的核心主体；用户明确的“允许改动、必须保留、禁止改动”优先。

## 请求与费用保护

对于 OpenAI Images 编辑兼容路由，主图以 multipart 字段 `image` 发送，参考图依序以 `image[]` 发送到已选中的编辑路由（通常是供应商提供的 `/images/edits` 端点）。普通文字生图仍走原有生成请求，不会因为这项功能改变请求形状。

当某个供应商、模型和请求形状尚无图片输入能力记录时，用户已经明确要求的这一次真实编辑可以作为唯一的能力确认请求。系统不会先额外探测，也不会在失败后自动重试、自动切换供应商、切换传输协议或降级为纯文字生图。

供应商已经收到请求后，即使没有返回可用图片，也可能已经计费。结果会如实保留实际状态、是否可能计费和是否收到输出；成功会记录该精确供应商、模型、端点和请求形状的能力证据，明确拒绝则不会被标记为支持。

## 验收标准

- 用户可只在 Codex 对话中完成单图编辑和多图产品/模特组合，不修改 Studio。
- 首图稳定作为主图，后续最多五张参考图按附件顺序传递。
- 第七张输入图本地拒绝且零供应商请求。
- 普通文字生图请求保持不变。
- 未知图片输入能力只允许用户明确发起的一次真实编辑；失败无自动重试或降级。
- 插件包包含本工作流的 Skill，并以 v1.0.2 进行验证和本地安装冒烟测试。
